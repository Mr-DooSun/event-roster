# 프로젝트 조직 제외 및 참가 명단 사용성 개선 설계

- 작성일: 2026-07-27
- 상태: 사용자 문서 검토 대기
- 변경 범위: 프로젝트 조직 제외 정책, 프로젝트 개요 조직 집계, 참가자 추가 모달, 참가 명단 필터
- 유지 범위: 전역 조직 생명주기, 프로젝트·명단 상태 전이, 자체 계정/JWT, 감사 이력, Excel 원본 비보관
- 대체 규칙: `2026-07-22-project-centered-roster-design.md`의 프로젝트 조직 연결 해제 판단에서 감사 기록을 업무 이력으로 간주하던 규칙

## 1. 목표

프로젝트에 잘못 추가한 조직은 업무 데이터가 없다면 목록에서 깨끗하게 제거하고, 이미 명단이나 예상 인원 기록이 있다면 과거 데이터를 보존한 채 비활성화한다. 운영자는 두 저장 방식의 차이를 직접 선택하지 않고 `프로젝트에서 제외`라는 하나의 업무 동작만 수행한다.

프로젝트 개요에서는 의미 없는 비활성 0명 조직을 숨기되 과거 집계가 있는 비활성 조직은 상태를 명확히 표시한다. 참가 명단 화면과 참가자 추가 모달은 입력 요소와 버튼 사이의 간격을 정돈하고, 소속 조직은 입력으로 검색한 뒤 유효한 조직을 선택하는 콤보박스로 바꾼다.

## 2. 프로젝트 조직 제외 정책

### 사용자 동작

활성 프로젝트 조직에 표시하는 destructive action의 이름을 `사용 중지`에서 `프로젝트에서 제외`로 바꾼다. 운영자에게 `비활성화`와 `제거`를 별도 선택지로 노출하지 않는다.

버튼을 누르면 업무 이력 유무에 맞는 확인 대화상자를 표시한다.

- 업무 이력 없음: `이 조직을 프로젝트에서 제외할까요? 다시 추가할 수 있습니다.`
- 업무 이력 있음: `기존 명단과 집계를 보존하기 위해 사용 중지 상태로 전환됩니다.`

비활성 연결에는 기존처럼 `다시 사용`을 제공한다. 전역 조직이 비활성 상태라면 프로젝트 연결을 다시 사용할 수 없다.

### 저장 규칙

제외 결과는 다음과 같이 서버가 결정한다.

| 프로젝트 조직 상태 | 처리 | 조직 탭 결과 |
| --- | --- | --- |
| 명단과 예상 스냅샷이 모두 없음 | `project_organizations` 연결 행 삭제 | 목록에서 사라짐 |
| 명단 또는 예상 스냅샷이 하나 이상 있음 | `project_organizations.is_active=0` | 비활성 상태로 유지 |

감사 로그는 제거 가능 여부를 결정하는 업무 이력에 포함하지 않는다. 따라서 조직 추가 감사 로그만 있는 연결은 삭제할 수 있다. 연결 행이 삭제돼도 기존 감사 로그는 삭제하지 않으며 `PROJECT_ORGANIZATION_REMOVED`를 추가한다.

삭제한 조직을 같은 프로젝트에 다시 추가하면 새 연결 행을 만들고 `PROJECT_ORGANIZATION_ADDED`를 기록한다. 과거 감사 로그가 존재한다는 이유만으로 새 연결을 비활성화 대상으로 취급하지 않는다. 업무 이력이 있는 비활성 연결을 다시 추가하면 기존 행을 재활성화하고 `PROJECT_ORGANIZATION_REACTIVATED`를 기록한다.

`hasHistory`처럼 의미가 넓은 이름 대신, UI 확인과 서버 분기에 사용하는 값은 명단·예상 스냅샷만 뜻하는 `hasBusinessHistory`로 명시한다.

### 동시성

제외 mutation은 기존 프로젝트 revision과 guarded D1 batch를 유지한다. 확인 대화상자를 연 뒤 다른 요청으로 명단이나 예상 스냅샷이 생겨도 서버는 mutation 실행 시점의 업무 이력을 다시 판정한다.

- 실행 시점에 업무 이력이 생겼다면 삭제하지 않고 비활성화한다.
- 프로젝트 revision이 달라졌다면 `STALE_REVISION`을 반환하고 화면은 최신 프로젝트·조직 데이터를 다시 읽는다.
- 프로젝트가 종료됐거나 만료됐다면 기존 `PROJECT_CLOSED` 처리를 유지한다.

## 3. 프로젝트 개요 조직 집계

조직의 유효 활성 상태는 프로젝트 연결과 전역 마스터가 모두 활성인 경우다.

```text
effectiveActive = projectOrganization.isActive && organization.isActive
```

프로젝트 개요와 Excel 요약 시트의 조직별 현황에는 다음 규칙을 동일하게 적용한다.

- 유효 활성 조직은 집계가 모두 0이어도 표시한다.
- 프로젝트 연결 또는 전역 마스터가 비활성이면서 `expected`, `inProgressAdded`, `inProgressCancelled`, `final`이 모두 0이면 숨긴다.
- 비활성이면서 네 값 중 하나라도 0이 아니면 과거 집계를 보존해 표시한다.
- 보존된 비활성 조직에는 `비활성` 상태 배지를 표시한다.
- 프로젝트 전체 예상·실제·증감 합계는 화면에 표시되는 조직 행을 기준으로 계산한다.

요약 API의 조직 행에는 프로젝트 연결과 전역 마스터 상태를 구분할 수 있는 `isActive`, `masterIsActive`를 포함한다. 데이터베이스 행은 변경하거나 삭제하지 않는다. 프로젝트의 조직 탭에는 비활성 연결도 계속 표시해 운영과 감사에 사용한다.

## 4. 참가자 추가 모달

모달 본문은 공통 dialog form 레이아웃을 사용한다.

```text
제목
모드 선택 버튼 행

참가자 선택
확정 이름
확정 소속 조직

하단 작업 버튼 행
```

- 모드 선택 버튼 사이에는 공통 action gap을 적용한다.
- 각 필드 사이에는 `--er-space-4` 수준의 세로 간격을 적용한다.
- `명단에 추가` 또는 `참가자 생성 후 추가`와 `닫기`를 같은 하단 action 영역에 배치한다.
- mutation 중에는 기존처럼 중복 제출과 모달 닫기를 막고 입력값을 보존한다.
- 좁은 화면에서는 입력 필드가 한 열을 유지하며, 하단 버튼은 줄바꿈돼도 서로 붙지 않는다.

## 5. 검색 가능한 소속 조직 선택

기존 참가자 모드의 `확정 소속 조직`과 새 참가자 모드의 `소속 조직`을 동일한 선택 전용 조직 콤보박스로 바꾼다.

### 후보 범위와 선택 규칙

- 현재 프로젝트에 연결된 유효 활성 조직만 후보로 사용한다.
- 입력값은 Unicode NFKC 정규화, trim, locale 소문자 변환 후 조직 이름의 부분 일치로 검색한다.
- 입력 문자열 자체는 조직 ID가 아니며 목록에서 하나를 선택해야 유효하다.
- 선택 후 입력을 다시 수정하면 기존 선택을 즉시 해제한다.
- 유효한 선택이 없으면 제출 버튼을 비활성화한다.
- 결과가 없으면 목록에 `일치하는 조직이 없습니다.`를 표시한다.
- 이 콤보박스에서는 조직을 생성하지 않는다.

조직 담당자가 기존 참가자를 추가할 때 소속 변경 권한이 없다면 현재 조직명을 읽기 전용 컨트롤로 표시한다. 운영자는 검색과 변경이 가능하다.

### 접근성 및 조작

- 입력에는 `role="combobox"`, `aria-autocomplete="list"`, `aria-expanded`, `aria-controls`, `aria-activedescendant`를 제공한다.
- 후보 영역은 `role="listbox"`, 각 후보는 `role="option"`을 사용한다.
- `ArrowDown`·`ArrowUp`으로 후보 이동, `Enter`로 선택, `Escape`로 목록 닫기를 지원한다.
- 입력 focus 시 전체 후보를 열고, blur 또는 선택 후 목록을 닫는다.
- 선택된 조직명은 입력에 남긴다.

프로젝트 조직 추가용 기존 `OrganizationCombobox`에는 “새 조직 생성”이라는 다른 책임이 있으므로 그대로 억지로 확장하지 않는다. 공통 검색·키보드 로직을 작은 선택 전용 컴포넌트로 분리하거나, 중복이 작다면 참가 명단 기능 안에 `OrganizationSelectCombobox`를 둔다. 구현 시 기존 접근성 동작과 정규화 함수는 재사용한다.

## 6. 참가 명단 화면 간격

명단 검색·조직 필터·상태 필터를 반응형 필터 그리드로 표시한다.

- 넓은 화면: 검색 필드는 남은 폭을 더 많이 사용하고 두 select는 일정한 최소 폭을 가진다.
- 좁은 화면: 세 필드를 한 열로 쌓는다.
- 필드 내부 라벨과 컨트롤 간격은 기존 `.er-field` 토큰을 유지한다.
- 필터 그룹과 명단 표 사이에는 `--er-space-5` 이상의 여백을 둔다.
- 상단 Excel action과 `참가자 추가`는 공통 action row gap을 유지하고 줄바꿈을 허용한다.
- 새 spacing 값은 하드코딩하지 않고 기존 디자인 토큰을 사용한다.

빈 명단에서도 필터 영역과 표 header가 서로 붙지 않으며, 데이터가 로딩 중일 때 기존 스켈레톤 배치를 깨뜨리지 않는다.

## 7. 컴포넌트와 데이터 흐름

```text
ProjectOrganizationsPanel
  → 제외 확인
  → PATCH project organization
  → 서버가 hard remove 또는 soft deactivate 결정
  → 프로젝트 revision과 조직 목록 갱신

ProjectDetailPage
  → summary API
  → 표시 대상 조직만 포함된 ProjectSummary
  → ProjectOverview / Excel export가 같은 집계 규칙 사용

ProjectRosterPage
  → 현재 프로젝트의 조직 목록
  → ParticipantDialog
  → OrganizationSelectCombobox
  → 선택된 organizationId로 기존 roster mutation 호출
```

검색형 선택은 프론트엔드 상태만 추가하며 API 요청 형태는 바꾸지 않는다. 기존 참가자는 `confirmedParticipant.organizationId`, 새 참가자는 `newParticipant.organizationId`를 계속 전송한다.

## 8. 오류 처리

- 후보 조직이 mutation 직전에 비활성화되면 서버의 기존 `VALIDATION_FAILED` 응답을 표시하고 모달 입력을 보존한다.
- 선택한 조직이 후보 목록 갱신으로 사라지면 선택을 해제하고 제출을 막는다.
- 제외 mutation 실패 시 확인 대화상자를 닫지 않거나 입력 맥락을 유지하고 기존 공통 오류 메시지를 표시한다.
- 요약 API 실패와 명단 로딩 실패는 기존 재시도 가능한 오류 UI를 유지한다.
- 검색 결과 없음은 오류 alert가 아니라 콤보박스의 비활성 안내 행으로 표시한다.

## 9. 테스트 전략

테스트는 RED → 최소 구현 → GREEN 순서로 작성한다.

### Worker 및 계약

- 조직 추가 감사만 있는 프로젝트 연결은 실제로 삭제되고 제거 감사가 남는다.
- 명단 또는 예상 스냅샷이 있는 연결은 비활성화되고 기록이 보존된다.
- 과거 감사만 있는 삭제 조직을 다시 추가한 뒤 업무 데이터 없이 다시 제외할 수 있다.
- mutation 도중 업무 이력이 생기는 경쟁 상황에서 hard delete 대신 soft deactivate한다.
- 활성 0명 조직은 요약에 포함한다.
- 비활성 0명 조직은 요약에서 제외한다.
- 비활성이지만 과거 수치가 있는 조직은 상태 필드와 함께 요약에 포함한다.
- 요약 합계와 Excel summary가 같은 표시 규칙을 사용한다.

### React

- 참가자 모달의 모드 버튼과 하단 버튼이 각각 spacing container에 포함된다.
- 필터가 반응형 전용 class를 사용하고 표와 분리된다.
- 조직명 일부 입력 시 일치하는 활성 조직만 표시한다.
- 키보드로 조직을 선택할 수 있다.
- 선택 후 입력 변경 시 선택이 해제되고 제출 버튼이 비활성화된다.
- 결과가 없을 때 안내 문구가 표시된다.
- 조직 담당자의 읽기 전용 소속 규칙을 유지한다.
- pending 또는 실패 mutation 중 입력값과 모달 상태를 유지한다.

### 회귀

- 프로젝트 조직 추가·재활성화·전역 비활성 제약
- 참가자 기존 선택·신규 생성·복원·소속 변경 권한
- 참가 명단 검색·조직 필터·상태 필터
- Excel export와 프로젝트 개요 합계
- 전체 typecheck, format, unit/integration test, web build, Worker dry-run

## 10. 완료 기준

- 운영자는 프로젝트 조직에 대해 `프로젝트에서 제외` 하나만 선택한다.
- 업무 데이터가 없는 연결은 조직 탭에서 사라지고, 업무 데이터가 있는 연결은 비활성 상태로 보존된다.
- 감사 로그는 두 경우 모두 남고 제거 판단을 방해하지 않는다.
- 비활성 0명 조직은 개요와 Excel 요약에 나타나지 않는다.
- 과거 집계가 있는 비활성 조직은 `비활성` 표시와 함께 유지된다.
- 참가자 추가 모달과 명단 필터의 요소·버튼 간격이 데스크톱과 모바일에서 구분된다.
- 소속 조직은 입력 검색 후 유효한 후보를 선택해야만 제출할 수 있다.
- 기존 권한, 명단 mutation, 프로젝트 revision, 로딩·오류 처리의 회귀가 없다.

## 11. 범위 밖

- 전역 조직 삭제
- 참가자 추가 모달에서 새 조직 생성
- 참가자 자체를 이름으로 검색하는 콤보박스 전환
- 서버 기반 조직 자동완성 endpoint
- 가상 스크롤 또는 외부 UI 라이브러리 도입
- 프로젝트 조직의 비활성화와 제거를 별도 버튼으로 노출
