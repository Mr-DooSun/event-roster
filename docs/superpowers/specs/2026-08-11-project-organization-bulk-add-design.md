# 프로젝트 조직 일괄 추가 설계

- 작성일: 2026-08-11
- 상태: 사용자 설계 승인 완료, 문서 검토 대기
- 변경 범위: 일반 프로젝트 상세의 조직 추가 UI와 기존 활성 조직의 원자적 일괄 연결

## 목표

운영자가 프로젝트의 `조직` 탭에서 활성 전역 조직 여러 개를 검색·선택하고 한 번의 저장으로 연결한다. 현재의 단일 조직 추가와 달리, 저장 결과가 일부만 반영되는 상태를 허용하지 않는다.

## 범위와 제외

- 일반 프로젝트(`ORDINARY`)에서만 일괄 추가를 제공한다.
- 선택 대상은 삭제되지 않고 활성화된 기존 전역 조직이다.
- 신규 조직 생성은 현재의 이름 입력 및 확인 dialog를 통한 단건 생성·추가 흐름을 유지한다.
- 종료 프로젝트 이력 보정(`CLOSED_CORRECTION`)은 기존 단건 선택기를 유지한다. 이력 보정은 별도 규칙과 endpoint를 사용하므로 이 기능에 포함하지 않는다.
- 조직 제외, 담당자 관리, 명단 편집과 전역 조직 검색 API의 pagination은 변경하지 않는다.

## UX

일반 프로젝트의 기존 `조직 추가` combobox 카드를 다음 UI로 교체한다.

1. `조직 일괄 추가` 제목 아래에 조직명 검색 input을 둔다. 빈 검색어에서는 추가 가능한 전체 활성 조직을, 입력 시에는 canonical 이름에 검색어를 포함하는 조직만 보인다.
2. 결과는 정보형 2열 grid 카드로 표시한다. 각 카드는 checkbox, 조직명, 대표 담당자 표시(`대표 미지정` 가능), 연결된 프로젝트 수를 포함한다. 명단 인원은 프로젝트-조직 연결에 속한 값이므로, 아직 연결되지 않은 후보 카드에는 표시하지 않는다.
3. 이미 활성 연결된 조직은 `이미 추가됨` 상태의 비활성 카드로 보인다. 선택과 저장 대상에서 제외한다.
4. 비활성 연결은 다시 활성화할 수 있으므로 선택 가능 카드로 보인다. 기존 명단·집계가 다시 연결될 수 있다는 안내를 카드 또는 선택 영역에 표시한다.
5. 선택한 카드 수를 `선택한 N개 조직 추가` 버튼에 표시한다. N이 0이면 버튼은 비활성화한다.
6. 저장 중에는 검색, checkbox, 저장 버튼을 모두 비활성화한다. 성공하면 선택을 비우고 최신 프로젝트 정보와 목록을 다시 불러온다.
7. `새 조직 생성 후 추가`는 grid 밖의 별도 action으로 유지한다. 다중 선택한 상태에서는 새 조직 생성 흐름을 시작할 수 없게 하여, 생성과 일괄 연결을 섞지 않는다.

## API와 원자성

기존 단건 endpoint와 별도로 다음 endpoint를 추가한다.

```text
POST /api/v1/projects/:projectId/organizations/bulk
```

요청은 중복 없는 하나 이상의 조직 ID와 현재 프로젝트 revision을 받는다.

```json
{
  "organizationIds": ["org-1", "org-2"],
  "expectedProjectRevision": 7
}
```

서버는 다음을 하나의 guarded D1 batch로 수행한다.

- 운영자 권한, 프로젝트 미삭제·미종료 상태 및 expected revision 검증
- 각 ID가 활성이고 삭제되지 않은 전역 조직인지 검증
- 대상 중 활성 연결이 이미 존재하는지 검증
- 새 연결 생성 또는 비활성 연결 재활성화
- 프로젝트 revision을 정확히 1 증가
- 각 조직의 `PROJECT_ORGANIZATION_ADDED` 또는 `PROJECT_ORGANIZATION_REACTIVATED` 감사 이력 기록

어느 검증이나 statement라도 실패하면 batch 전체가 rollback된다. 성공 응답은 갱신된 `projectRevision`과 추가·재활성화된 조직 ID 목록을 반환한다. 단건 API의 계약과 동작은 그대로 유지한다.

`STALE_REVISION` 또는 대상 상태 변경으로 실패하면 UI는 선택을 유지하지 않고 최신 데이터를 불러온 뒤 재선택을 안내한다. 성공했지만 재조회가 실패하면 저장 성공과 재조회 실패를 구분해 안내한다.

## 구성 요소와 테스트

- 프런트엔드는 `ProjectOrganizationsPanel`에 다중 선택 상태와 bulk mutation을 추가하고, 검색·카드 grid는 별도 focused component로 분리한다.
- contracts에는 bulk request·response schema를 추가한다.
- worker route·service는 기존 `addProjectOrganization`의 권한, guarded atomic, 감사 패턴을 재사용하되 bulk 전용 검증과 mutation을 제공한다.
- worker 통합 테스트는 다중 신규 연결, 비활성 연결 재활성화, 중복 ID 거부, 이미 활성 연결된 대상 거부, 비활성·삭제 조직 거부, stale revision 및 rollback·감사 이력을 검증한다.
- web 테스트는 검색, 선택 수, 이미 추가된 카드 비활성화, 재활성화 안내, 저장 요청 payload, 성공 후 초기화와 stale revision 동작을 검증한다.
