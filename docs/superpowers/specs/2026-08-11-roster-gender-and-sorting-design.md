# 참가 명단 성별·정렬·표시 개선 설계

- 작성일: 2026-08-11
- 상태: 사용자 설계 승인 완료
- 변경 범위: 프로젝트 참가 명단의 표시·정렬·성별, 참가자 추가·수정, Excel 가져오기·내보내기

## 목표

참가 명단에서 내부 식별자인 고유 ID를 숨기고, 운영자가 조직·학년·이름 순으로
명단을 읽고 정렬할 수 있게 한다. 성별은 프로젝트 참가 시점의 스냅샷으로
`남성`, `여성`, `미지정`을 관리한다.

## 명단 UX

- 상태 변경 버튼의 보이는 라벨은 `취소` 또는 `복원`만 사용한다. 행의 참가자명은
  접근성 이름에 유지한다.
- 표의 고유 ID 열과 검색 대상에서 고유 ID를 제거한다. 내부 ID, API 식별, Excel
  내보내기 고유 ID 열은 유지한다.
- 기본 정렬은 `조직명 → 학년 → 이름` 오름차순이다. 학년은 `중1`부터 `고3`까지
  교육 과정 순서를 사용하고, 담당교사와 미지정은 그 뒤에 둔다.
- 정렬 선택은 `기본(조직·학년·이름)`, `조직순`, `학년순`, `이름순`을 제공한다.
  필터가 적용된 결과에만 정렬하며, 조직·학년·이름이 같을 때는 나머지 기본 키로
  안정적으로 정렬한다.
- 성별 열과 `전체/남성/여성/미지정` 필터를 추가한다.

## 성별 데이터

- 성별은 참가자 마스터의 영구 속성이 아니라 `project_roster_entries`의
  프로젝트별 스냅샷으로 저장한다.
- 허용 값은 `MALE`, `FEMALE`, `NULL`이며 화면·Excel에는 각각 `남성`, `여성`,
  `미지정`으로 표시한다.
- 기존 명단 migration 값은 `NULL`로 보존한다. 새 참가자 추가, 기존 참가자 연결,
  명단 정보 수정, 이력 보정은 성별 선택을 제공하되 미지정도 저장 가능하다.
- 새 Excel 템플릿과 가져오기는 `성별` 열을 받고 `남성`, `여성`, `미지정`(또는 빈 값)을
  매핑한다. 내보내기 명단에도 `성별` 열을 포함한다.

## API·저장·검증

- contracts에 성별 enum과 roster profile schema 필드를 추가한다.
- 명단 조회, 일괄 참가자 추가, 단건 추가, 수정, 이력 보정, import/export의 DTO와
  worker SQL projection·mutation에 성별 스냅샷을 포함한다.
- D1 migration은 `gender_snapshot` nullable column과 profile snapshot 검증 trigger를
  추가한다. 기존 role/grade 검증과 독립적으로 성별 enum 값만 제한한다.
- 모든 mutation과 import는 기존 revision·권한·원자성 규칙을 유지한다.

## 검증

- contracts와 worker integration 테스트: 성별 저장·조회·수정, migration 호환,
  Excel 성별 import/export, 잘못된 성별 거부를 검증한다.
- web 테스트: 고유 ID 비표시·검색 제외, 취소/복원 라벨, 기본/선택 정렬, 성별
  필터·표시·입력값을 검증한다.
