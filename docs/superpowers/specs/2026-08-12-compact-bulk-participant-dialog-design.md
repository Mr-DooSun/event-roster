# 신규 참가자 일괄 추가 모달 컴팩트 레이아웃 설계

## 목표

신규 참가자 일괄 추가 모달의 전체 높이와 각 참가자 입력 카드의 높이를 줄인다. 삭제와 행 추가 동작을 자연스러운 위치로 옮기고, 여러 참가자를 빠르게 훑을 수 있도록 카드 간 구분감을 강화한다.

## 모달 구조

- 변경 범위는 `새 참가자` 모드의 일괄 입력 화면으로 한정한다. `기존 참가자` 모드의 필드와 동작은 변경하지 않는다.
- 명단 모달의 최대 높이는 화면 높이의 약 80%로 제한한다. 제목, 모드 전환, 소속 조직, 하단 최종 작업 영역은 유지하고 참가자 카드 목록만 내부에서 스크롤한다.
- 작은 화면에서는 사용 가능한 화면 높이를 우선 사용해 입력 영역이 지나치게 작아지지 않도록 기존 모바일 동작을 유지한다.
- 최종 저장 영역의 `닫기`와 `N명 명단에 추가` 버튼은 모달 하단에 유지한다. 이 버튼들은 참가자 입력 행을 추가하는 버튼과 역할이 다르므로 위치와 강조 수준을 구분한다.

## 컴팩트 참가자 카드

- 각 참가자 카드는 상단에 `N번 참가자` 제목을 표시한다.
- 삭제 동작은 카드 우측 상단의 `×` 아이콘 버튼으로 표시한다. 버튼에는 `N번 참가자 삭제`라는 접근 가능한 이름을 유지한다.
- 큰 빨간색 `삭제` 버튼 영역은 제거한다. `×`는 기본 상태에서 중립색이고 hover 및 focus 상태에서 위험 색상으로 강조한다.
- 데스크톱에서는 이름, 성별, 참가자 구분, 학년을 한 행에 배치한다. 필드 라벨에서 반복되는 `N번` 접두사는 제거하고 카드 제목으로 참가자 번호를 전달한다.
- 카드의 세로 패딩과 카드 사이 간격을 줄이고, 얇은 테두리와 옅은 배경색을 함께 사용해 인접 카드가 분명히 구분되도록 한다.
- 오류 또는 중복 안내는 해당 필드 아래에 그대로 표시한다. 안내가 없는 정상 카드만 낮아지고, 오류가 있는 카드는 필요한 만큼 자연스럽게 늘어난다.
- 좁은 화면에서는 필드를 1열 또는 2열로 재배치해 입력 너비와 터치 영역을 보장한다.

## 참가자 행 추가 및 빈 상태

- 현재 목록 위에 있는 `참가자 추가` 버튼을 제거하고 목록 아래로 이동한다.
- 목록 아래에 `+ 참가자 추가` 버튼을 전체 너비로 표시한다. 최대 30명에 도달하거나 제출 중이면 기존처럼 비활성화한다.
- `등록 예정 N명 / 최대 30명` 정보는 목록 상단의 작은 보조 텍스트로 유지해 현재 수량을 먼저 확인할 수 있게 한다.
- 마지막 참가자도 삭제할 수 있다. 행이 0개가 되면 입력 카드 대신 `등록할 참가자가 없습니다.`라는 짧은 빈 상태 안내와 전체 너비 `+ 참가자 추가` 버튼을 표시한다.
- 행이 0개일 때 최종 `명단에 추가` 버튼은 기존 검증 규칙대로 비활성화한다.
- 새 행을 추가하면 기존과 동일한 기본값으로 빈 참가자 초안을 하나 생성하고 중복 확인 상태를 초기화한다.

## 상태 및 동작

- 참가자 초안 데이터 구조와 최대 30명 제한은 변경하지 않는다.
- 행 삭제 시 해당 행만 제거하고 중복 확인 상태를 초기화하는 기존 동작을 유지한다.
- 행을 모두 삭제해도 모달, 선택한 조직, 모드 상태는 유지한다.
- 제출 중에는 추가, 삭제, 입력, 닫기 동작의 기존 비활성화 정책을 유지한다.
- 이름, 학년, 중복 참가자 검증 및 오류 문구는 변경하지 않는다.

## 접근성

- 각 카드는 `fieldset`과 숨김 `legend`를 유지해 참가자별 입력 그룹으로 인식되게 한다.
- 시각적 카드 제목은 스크린 리더에서 중복 낭독되지 않도록 `legend`와 연결 방식을 명확히 한다.
- `×` 버튼의 시각적 기호와 별개로 `N번 참가자 삭제` 접근 가능한 이름을 제공한다.
- 전체 너비 추가 버튼은 키보드로 접근 가능하며 `참가자 추가`라는 기존 접근 가능한 이름을 유지한다.
- 모든 focus 표시와 비활성 상태를 기존 디자인 시스템 규칙에 맞춘다.

## 검증

- 추가 버튼이 참가자 목록 아래에 있고 전체 너비 스타일을 사용하는지 검증한다.
- 각 카드의 삭제 버튼이 `×`로 표시되고 `N번 참가자 삭제` 접근 가능한 이름을 갖는지 검증한다.
- 마지막 행 삭제가 허용되며 빈 상태 안내와 추가 버튼이 남는지 검증한다.
- 빈 목록에서 참가자 추가 시 새 입력 카드가 다시 생성되는지 검증한다.
- 30명 제한, 제출 중 비활성화, 중복 확인 초기화가 기존처럼 동작하는지 검증한다.
- 신규 참가자 모드에 컴팩트 전용 클래스와 스크롤 영역이 적용되는지 검증한다.
- 기존 참가자 모드, 검증 오류, 최종 제출, Escape 및 포커스 동작이 회귀하지 않는지 검증한다.
