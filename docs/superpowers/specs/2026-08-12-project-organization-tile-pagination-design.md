# 프로젝트 조직 타일·페이지네이션 설계

## 목표

프로젝트 상세의 조직 탭에서 각 조직을 독립적인 정보 단위로 명확히 구분하고, 현재 명단 인원수를 가장 먼저 인지할 수 있게 한다. 조직 수가 많아도 화면이 지나치게 길어지지 않도록 클라이언트 페이지네이션을 제공한다.

## 레이아웃

- 기존 세로 목록을 카드형 타일 그리드로 교체한다.
- 데스크톱에서는 2열, 좁은 화면에서는 1열로 표시한다.
- 타일의 높이는 같은 행에서 자연스럽게 맞추고, 긴 조직명과 보조 정보는 줄바꿈을 허용한다.
- 조직마다 조직 ID로 계산한 안정적인 팔레트 색을 왼쪽 강조선에 사용한다. 같은 조직은 다시 렌더링하거나 페이지를 이동해도 같은 색을 유지한다.
- 색상은 구분 보조 수단으로만 사용하고 조직명 텍스트, 테두리, 간격으로도 카드 경계를 명확히 한다.

## 타일 정보 위계

타일은 위에서 아래 순서로 다음 정보를 표시한다.

1. 조직명과 `사용 중` 또는 `사용 중지` 상태
2. 현재 명단 인원수
3. 대표 조직장과 담당자 수
4. 담당자 지정 링크와 프로젝트 제외 또는 다시 사용 버튼

현재 명단은 큰 숫자와 작은 `명` 단위로 표현한다. `0명`도 숨기지 않고 같은 위치와 크기로 표시해 조직 간 비교가 가능하게 한다. 대표 조직장과 담당자 수는 보조 색상과 작은 글자 크기를 사용한다.

기존 삭제·사용 중지 상태의 의미와 버튼 권한, 로딩 상태, 제외 확인 다이얼로그 동작은 변경하지 않는다. 관리 권한이 없으면 기존처럼 담당자 지정 링크나 변경 버튼을 표시하지 않는다.

## 페이지네이션

- 활성 상태와 권한 정책을 적용한 기존 `visibleMemberships` 결과를 페이지 단위로 나눈다.
- 기본 페이지 크기는 8개 조직으로 고정한다. 페이지 크기 선택 기능은 이번 범위에 포함하지 않는다.
- 타일 아래에 `총 N개 조직 · A–B개 표시`, 이전·다음 버튼과 페이지 번호를 표시한다.
- 조직 추가, 제외, 다시 사용 또는 외부 갱신으로 목록 길이가 바뀌어 현재 페이지가 범위를 벗어나면 마지막 유효 페이지로 보정한다.
- 결과가 없으면 기존 `연결된 조직이 없습니다.` 문구를 표시하고 페이지네이션은 표시하지 않는다.
- 현재 페이지 외 조직도 데이터에서 제거하지 않으며, 표시는 클라이언트에서만 나눈다.

## 반응형과 접근성

- 모바일에서는 1열로 전환하고 액션 영역을 줄바꿈해 버튼과 링크가 겹치지 않게 한다.
- 페이지네이션은 `nav`와 명확한 접근성 이름을 사용한다.
- 현재 페이지 버튼에 `aria-current="page"`를 지정하고, 첫 페이지와 마지막 페이지에서 각각 이전·다음 버튼을 비활성화한다.
- 상태와 조직 구분은 색상만으로 전달하지 않는다.

## 구현 경계

- 서버 API, 데이터베이스, 계약 스키마는 변경하지 않는다.
- 프로젝트 조직 추가 모달의 후보 그리드는 변경하지 않는다.
- 조직 검색, 필터, 정렬, 페이지 크기 선택은 추가하지 않는다.
- 참가 명단 탭의 조직 배지 팔레트와 같은 방식의 안정적 색상 계산을 재사용하되, 타일에는 배지가 아니라 왼쪽 강조선으로 적용한다.

## 검증

- 조직 타일이 2열 그리드용 구조와 안정적인 색상 인덱스를 갖는지 검증한다.
- 조직명, 상태, 대표 조직장, 담당자 수, 현재 명단 수와 권한별 액션이 유지되는지 검증한다.
- 명단 인원수가 강조 요소로 분리되고 `0명`도 표시되는지 검증한다.
- 9개 이상의 조직에서 기본 8개 표시, 다음 페이지 이동, 표시 범위와 현재 페이지 접근성 속성을 검증한다.
- 목록 축소 시 페이지 보정, 빈 목록에서 페이지네이션 미표시를 검증한다.
- 웹 전체 테스트, 타입 검사, Biome 검사와 프로덕션 빌드를 실행한다.
