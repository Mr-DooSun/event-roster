# 종료 프로젝트 명단 성별 수정 오류 설계

## 문제

종료 프로젝트의 이력 보정 화면에서 참가자 정보 수정 창은 성별을 입력받지만, `ProjectRosterPage`가 이력 보정 PATCH 요청을 만들 때 `gender`를 누락한다. 성별만 바꾸면 서버는 기존 스냅샷과 요청 결과가 같다고 판단해 `CONFLICT`를 반환하고, 화면에는 일반 명단 변경 실패 안내가 표시된다.

## 변경 범위

- 이력 보정 참가자 수정 요청에 수정 창에서 받은 `gender`를 포함한다.
- 일반 프로젝트의 참가자 수정 요청 동작과 서버·데이터베이스 스키마는 변경하지 않는다.
- 변경 사항이 전혀 없는 저장 요청의 기존 서버 충돌 처리는 이번 수정 범위에서 유지한다.

## 데이터 흐름

1. `ParticipantEditDialog`가 이름, 조직, 참가자 구분, 학년, 성별을 `onSave`에 전달한다.
2. `ProjectRosterPage`가 이력 보정 모드이면 모든 편집 필드를 `ClosedProjectRosterPatchRequestSchema` 형식으로 전송한다.
3. 워커의 `patchClosedProjectRoster`가 `gender_snapshot`을 갱신하고 새 명단 스냅샷을 반환한다.
4. 화면이 최신 프로젝트와 명단을 다시 불러와 변경된 성별을 표시한다.

## 오류 처리

프로젝트 또는 명단 revision이 오래된 경우의 `STALE_REVISION`, 프로젝트 상태 오류, 권한 오류 등 기존 처리를 유지한다. 이번 오류의 원인이었던 누락된 성별 때문에 발생하는 `CONFLICT`만 제거한다.

## 테스트

- 이력 보정 화면에서 성별만 변경해 저장할 때 PATCH 요청 body에 변경된 `gender`가 포함되는 회귀 테스트를 먼저 추가한다.
- 테스트가 현재 코드에서 실패하는지 확인한 후 최소 구현을 적용한다.
- 웹 테스트, 워커 테스트, 타입/정적 검사를 실행한다.
