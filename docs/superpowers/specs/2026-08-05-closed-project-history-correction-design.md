# 종료 프로젝트 이력 보정 설계

## 1. 목적

종료된 프로젝트에 누락된 조직과 참가 명단을 사후 입력하고 잘못된 역사
데이터를 수정할 수 있게 한다. 프로젝트는 계속 `CLOSED` 상태를 유지하며,
일반 운영 재개와 종료 후 이력 보정을 분리한다.

이 기능은 과거 기록을 복원하는 운영자 전용 기능이다. 조직 담당자는 종료
프로젝트를 계속 읽기 전용으로 사용한다.

## 2. 확정 정책

- 비부트스트랩 운영자만 종료 프로젝트 이력을 보정할 수 있다.
- 프로젝트 상태, 종료 시각, 종료 사유는 보정 중에도 변경하지 않는다.
- 조직 연결과 참가 명단의 추가·수정·제외·취소·복원을 허용한다.
- 수동 입력과 엑셀 가져오기를 모두 허용한다.
- 종료 후 추가한 참가자는 예상 인원이 아닌 실제 참석 인원으로 집계한다.
- 종료 프로젝트의 참가자 수정은 해당 프로젝트의 명단 스냅샷만 변경한다.
- 모든 보정은 변경자·시각·변경 전후 값과 함께 `종료 후 이력 보정`으로
  감사 로그에 구분한다. 사용자가 별도 보정 사유를 입력하지는 않는다.
- 사용 중·사용 중지·삭제 조직을 모두 역사 연결 대상으로 선택할 수 있다.
  이 연결은 현재 권한을 부여하지 않는다.

## 3. 상태와 권한 경계

새 프로젝트 상태를 추가하지 않는다. 종료 상세 화면의 `이력 보정 시작`은
현재 브라우저 화면의 명시적 작업 모드일 뿐 서버 상태가 아니다.

서버에는 일반 변경 API와 분리된 종료 이력 보정 API를 둔다. 모든 보정
요청은 다음 조건을 선조회와 원자적 쓰기 guard에서 모두 검증한다.

- 요청자는 비부트스트랩 `OPERATOR`다.
- 프로젝트가 존재하고 삭제되지 않았다.
- 프로젝트 상태가 `CLOSED`다.
- 요청의 예상 project revision이 현재 revision과 같다.

조직 담당자, bootstrap 계정, 인증되지 않은 사용자는 보정 API를 호출할 수
없다. 종료 프로젝트에 연결된 조직은 담당자의 현재 권한 범위에 포함되지
않는다. 보정 도중 프로젝트가 재개되거나 삭제되면 쓰기와 감사 로그를 함께
롤백하고 최신 프로젝트를 다시 읽게 한다.

## 4. 컴포넌트와 API 경계

기존 화면 구성과 입력 컴포넌트는 재사용하되, `CLOSED` 상태에서는 전용
보정 서비스로 요청한다. 일반 서비스의 `PROJECT_CLOSED` 차단을 운영자에게
예외 처리하지 않는다.

전용 서비스는 다음 책임으로 분리한다.

1. 프로젝트 조직 보정
   - 기존 또는 신규 조직 연결
   - 사용 중지·삭제 조직 검색과 역사 연결
   - 프로젝트 안에서의 연결 활성·비활성 상태 수정
   - 조직 제외와 같은 연결 재활성화
2. 명단 보정
   - 기존 참가자 또는 새 참가자의 단건·일괄 추가
   - 프로젝트 명단 스냅샷의 이름·소속 조직·역할·학년 수정
   - 명단 취소와 복원
3. 엑셀 보정
   - 클라이언트에서 읽은 행 검증
   - 서버 전체 검증과 원자적 반영
4. 감사 기록
   - `CLOSED_PROJECT_ORGANIZATION_CORRECTED`,
     `CLOSED_PROJECT_ROSTER_CORRECTED`,
     `CLOSED_PROJECT_ROSTER_IMPORTED` 액션
   - 세부 작업 종류와 대상, 변경 전후 값을 기록

각 요청은 하나의 guarded D1 batch 안에서 대상 변경, project revision 증가,
감사 로그 삽입을 함께 수행한다. 하나라도 실패하면 전체를 롤백한다.

## 5. 데이터 규칙

### 5.1 종료 후 명단 추가

종료 후 추가한 명단 행은 다음 값으로 저장한다.

- `source = IN_PROGRESS`
- `status = ACTIVE`
- `was_expected_at_start = false`

사전등록 스냅샷과 예상 인원은 바꾸지 않는다. 실제 인원, 진행 중 추가,
학생·교사 수와 증감만 기존 집계식으로 다시 계산한다. 이후 취소하면 실제
인원에서 제외하고 기존 명단 상태 규칙에 따라 집계한다.

### 5.2 참가자 기본정보와 역사 스냅샷

기존 참가자를 종료 프로젝트에 추가할 때 참가자 기본정보를 갱신하지 않는다.
선택·확정한 이름, 조직, 역할과 학년을 프로젝트 명단 스냅샷에 복사한다.

종료 프로젝트에서 참가자를 수정할 때도 명단 스냅샷만 변경한다. 참가자
기본정보와 다른 프로젝트의 명단은 바뀌지 않는다. 새 참가자는 안정적인 고유
ID와 FK를 위해 참가자 기본 레코드를 생성하지만, 종료 프로젝트의 역사 표시는
그 시점의 명단 스냅샷을 기준으로 한다. 참가자 기본정보가 나중에 바뀌어도
종료 프로젝트 기록은 유지된다.

### 5.3 조직 역사 연결

사용 중·사용 중지·삭제 조직을 모두 선택할 수 있다. 사용 중지 조직은
`비활성`, 삭제 조직은 `삭제됨`으로 표시한다. 이 연결은 담당자 권한이나
일반 선택 범위를 복원하지 않는다.

이력 보정은 조직 마스터의 이름·사용 상태·삭제 상태를 수정하지 않는다.
프로젝트 안에서의 연결 상태와 명단에 저장된 조직 스냅샷만 변경한다.

종료 프로젝트에서 조직을 제외할 때 참조 유무와 관계없이 연결 행을 물리
삭제하지 않고 `is_active = 0`으로 보존한다. 다시 추가하면 동일한 연결을
재활성화한다.

### 5.4 엑셀 가져오기

원본 파일은 서버에 저장하지 않는다. 기존과 같이 클라이언트가 행을 읽고
서버가 조직, 참가자 프로필, 중복, 프로젝트 revision을 검증한다. 모든 행과
감사 기록은 한 원자적 작업으로 반영하며, 한 행이라도 실패하면 아무 행도
저장하지 않는다. 성공한 행은 모두 실제 참석 명단으로 기록한다.

## 6. 화면 흐름

종료 프로젝트 상세는 기본적으로 읽기 전용이다. 운영자에게만 `이력 보정
시작` 버튼을 표시한다.

보정 모드에서는 다음을 제공한다.

- 화면 상단의 `종료 후 이력 보정 중` 경고 배너
- 조직 탭의 추가·제외·재연결 기능
- 명단 탭의 단건·여러 명 추가, 수정, 취소·복원 기능
- 엑셀 가져오기
- `예상 인원은 변경되지 않고 실제 참석 인원에 반영됩니다.` 안내
- 서버 상태를 변경하지 않고 읽기 전용 화면으로 돌아가는 `이력 보정 종료`

프로젝트 재개·삭제 mutation이 진행 중이면 보정 컨트롤을 잠근다. 보정 성공
후 프로젝트, 조직 현황, 명단, 요약 통계와 감사 이력을 모두 다시 불러온다.

## 7. 오류 처리와 동시성

- revision 불일치: 현재 입력을 보존하고 `최신 이력을 불러왔습니다.`를 표시한
  뒤 최신 프로젝트와 관련 데이터를 다시 읽는다.
- 동시 재개: 보정 모드를 종료하고 일반 진행 중 화면으로 전환한다.
- 동시 삭제: 보정 모드를 종료하고 삭제 프로젝트 읽기 전용 화면으로 전환한다.
- 조직 상태 변경: 조직이 존재하는 한 역사 연결은 허용하며 최신 상태 배지를
  표시한다.
- 엑셀 형식·중복 오류: 행별 오류를 표시하고 서버에는 아무 데이터도 남기지
  않는다.
- guarded mutation 또는 감사 삽입 실패: 대상 변경, project revision과 감사
  로그를 모두 롤백한다.

## 8. 테스트 전략

### 계약·도메인

- 종료 이력 보정 요청 schema와 참가자 스냅샷 수정 규칙
- 종료 후 추가 명단의 source/status/예상 여부
- 예상 인원 불변과 실제·증감 집계

### Worker 통합

- 운영자 성공, 조직 담당자·bootstrap·미인증 요청 거부
- 비종료·삭제 프로젝트 거부
- 사용 중·사용 중지·삭제 조직의 역사 연결과 권한 비부여
- 조직 제외 시 연결 보존과 같은 연결 재활성화
- 참가자 스냅샷 수정 후 기본정보와 다른 프로젝트 불변
- 단건·일괄·엑셀 추가가 실제 참석으로 집계
- 엑셀 전체 성공 또는 전체 롤백
- revision 경쟁에서 한 요청만 성공
- 프로젝트 재개·삭제 경합과 감사 실패 시 전체 롤백
- 보정 전후 감사 로그의 actor, 세부 작업, before/after

### Web

- 운영자 전용 보정 시작·종료와 조직 담당자 읽기 전용
- 보정 배너와 실제 참석 반영 안내
- 조직 상태별 검색·배지와 연결 작업
- 단건·여러 명·엑셀 입력, 스냅샷 수정, 취소·복원
- stale·재개·삭제 오류 후 최신 상태 재조회
- 보정 종료 후 mutation 컨트롤 제거

### E2E

종료 프로젝트에 사용 중지 또는 삭제 조직을 연결하고 명단을 추가한다. 프로젝트
상태와 종료 시각이 유지되고, 예상 인원은 불변이며 실제 인원과 감사 이력이
갱신되는지 확인한다. 조직 담당자로 로그인했을 때 같은 프로젝트가 읽기
전용인지 검증한다.

## 9. 배포

기존 테이블과 컬럼만 사용하므로 D1 migration은 추가하지 않는다. 전체 테스트,
타입 검사, 포맷 검사, Web 빌드와 E2E를 통과한 main을 기존 수동 Cloudflare
절차로 배포한다. 배포 후 health, SPA와 운영자·조직 담당자 권한 smoke를
확인한다.

## 10. 제외 범위

- 프로젝트의 자동 재개 또는 재종료
- 종료 시각·종료 사유 변경
- 조직 담당자의 종료 이력 보정
- 별도 보정 사유 입력 필드
- 엑셀 원본 파일 서버 보관
- 참가자 기본정보나 다른 프로젝트 명단의 연쇄 수정
