# 참가 명단 페이지네이션·조직 배지·성별 추가 수정 설계

## 목표

참가 명단을 기본 정렬 순서와 같은 열 배치로 읽기 쉽게 만들고, 조직을 은은한 배지로 구분하며, 최대 130명의 명단을 페이지 단위로 탐색할 수 있게 한다. 참가자 추가의 모든 경로에서 선택한 성별이 명단 스냅샷에 저장되도록 누락된 데이터 흐름도 복구한다.

## 명단 열과 조직 표시

- 열은 `조직 → 학년 → 이름 → 참가자 구분 → 성별 → 상태 → 작업 → 등록 시점` 순서로 표시한다.
- 기본 정렬 우선순위는 기존 `조직 → 학년 → 이름`을 유지한다.
- 조직명은 텍스트가 포함된 둥근 배지로 표시한다.
- 배지 색은 조직 ID를 안정적인 팔레트 인덱스로 변환해 같은 조직에 항상 같은 색을 사용한다. 낮은 채도의 배경과 충분한 대비의 글자색을 사용하며 색상만으로 조직을 표현하지 않는다.
- 삭제 조직의 `삭제됨` 상태 배지는 기존 위험 색상을 유지해 조직 구분 배지와 혼동되지 않게 한다.

## 클라이언트 페이지네이션

- 명단 API와 화면의 기존 최대 처리량 130명은 유지한다.
- 검색과 모든 필터를 적용한 뒤 활성 정렬 기준으로 정렬하고, 마지막 단계에서 현재 페이지를 잘라 표시한다.
- 기본 페이지 크기는 30명이고 `30/60/100명` 중 선택할 수 있다.
- 하단에 `총 N명 · A–B명 표시`, 이전/다음 및 페이지 번호를 제공한다.
- 검색어, 조직·구분·학년·성별·상태 필터, 페이지 크기가 바뀌면 첫 페이지로 이동한다.
- 필터로 전체 페이지 수가 줄어 현재 페이지가 범위를 벗어나면 마지막 유효 페이지로 보정한다.
- 정렬 기준 변경은 같은 필터 결과 안에서 순서를 바꾸므로 첫 페이지로 이동한다.
- 결과가 없으면 `총 0명 · 0명 표시`를 제공하고 페이지 이동 버튼을 비활성화한다.

## 참가자 추가 성별 데이터 흐름

성별은 기존 정책대로 프로젝트 명단 스냅샷의 nullable 값이며 `미지정`, `남성`, `여성`을 허용한다.

### 새 참가자

`BulkParticipantRowsField`의 각 초안에 저장된 `gender`를 `ParticipantDialog`의 bulk submit payload에 포함한다. contracts와 bulk worker 서비스는 이미 이 필드와 `gender_snapshot` 저장을 지원하므로 누락된 웹 매핑을 복구한다.

### 기존 참가자

- 기존 참가자 탭에 `미지정/남성/여성` 선택 필드를 추가한다.
- 참가자를 바꾸면 성별은 `미지정`으로 초기화한다. 참가자 마스터에는 성별이 없으므로 다른 프로젝트의 성별을 자동 제안하거나 복사하지 않는다.
- `ExistingParticipantConfirmation`, roster create request와 worker 단건 추가 서비스가 성별을 전달한다.
- 신규 명단 행 생성과 취소된 명단 행 재활성화 모두 `gender_snapshot`을 갱신한다.
- SQL `RETURNING`과 응답 매퍼도 성별을 포함해 추가 직후 응답과 재조회가 일치하게 한다.

### 기존 명단

기존 `NULL` 성별은 이름으로 추정하거나 일괄 변환하지 않는다. 운영자는 정보 수정에서 필요한 행만 명시적으로 변경한다.

## 오류와 경계 조건

- 기존 revision, 프로젝트 상태, 조직 권한 및 원자성 검증은 유지한다.
- 잘못된 성별 enum은 contracts와 D1 trigger에서 계속 거부한다.
- 재활성화 시 성별을 포함한 최신 확인값으로 기존 스냅샷을 갱신한다.
- 페이지네이션은 표시 계층에만 적용하고 Excel 내보내기와 명단 집계에는 전체 필터 전 원본 데이터를 사용한다.

## 검증

- 웹 테스트에서 새 참가자 bulk payload와 기존 참가자 단건 payload에 선택한 성별이 포함되는지 검증한다.
- worker 통합 테스트에서 신규 단건 추가와 취소 행 재활성화의 `gender_snapshot`, API 응답 및 재조회 값을 검증한다.
- 표 테스트에서 헤더·셀 순서, 조직별 안정적 배지 클래스/스타일, 삭제 배지 공존을 검증한다.
- 페이지네이션 테스트에서 기본 30명, 30/60/100 선택, 페이지 이동, 조건·정렬 변경 초기화, 빈 결과와 범위 보정을 검증한다.
- 전체 tests, type checks, Biome 및 production build를 실행한다.
