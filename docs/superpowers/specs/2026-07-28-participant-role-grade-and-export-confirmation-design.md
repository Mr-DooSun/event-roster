# 참가자 구분·학년 및 Excel 내보내기 확인 설계

- 작성일: 2026-07-28
- 상태: 사용자 문서 검토 대기
- 변경 범위: 참가자 일괄 추가, 프로젝트별 참가자 구분·학년, 명단 조회·수정·필터, Excel 가져오기·내보내기, 프로젝트 요약
- 유지 범위: 참가자 고유 ID·이름·소속 조직 마스터, 프로젝트 상태 전이, 조직·계정 권한, 예상/실제 집계, 감사 이력, Excel 원본 미보관

## 1. 목표

새 참가자를 한 명씩 반복 입력하거나 여러 이름을 줄바꿈 텍스트로 붙여 넣는
대신, 최대 30명의 입력 행을 필요한 만큼 추가해 각 참가자의 이름, 참가자
구분, 학년을 정확하게 등록한다.

참가자 구분과 학년은 사람의 영구 속성이 아니라 해당 프로젝트에 참가했을
당시의 정보로 저장한다. 같은 사람이 다음 반기 또는 다음 해 프로젝트에 다시
참가하면 이전 값을 참고할 수 있지만, 새 프로젝트에 추가할 때 다시 확인한다.
따라서 과거 프로젝트의 역할과 학년은 이후 등록으로 바뀌지 않는다.

Excel 내보내기는 현재 화면 필터와 무관하게 취소자를 포함한 전체 명단을
내보낸다는 사실을 확인 대화상자에서 명확하게 안내하고, 사용자가 확정한
뒤에만 파일을 만든다.

## 2. 핵심 용어와 데이터 소유권

### 참가자 마스터

참가자 마스터는 다음 안정적인 식별 정보만 가진다.

- 고유 ID
- 이름
- 현재 소속 조직

학생, 담당교사, 학년은 참가자 마스터에 저장하지 않는다. 학년은 시간이
지나면 바뀌고 역할도 프로젝트마다 달라질 수 있기 때문이다.

### 프로젝트 명단 스냅샷

`project_roster_entries`는 기존 등록 시점과 상태 외에 다음 값을 가진다.

- `participant_role_snapshot`: `STUDENT`, `TEACHER`, 또는 기존 데이터용 `NULL`
- `student_grade_snapshot`: `M1`, `M2`, `M3`, `H1`, `H2`, `H3`, 또는 `NULL`

표시 문자열은 다음처럼 매핑한다.

| 저장 값 | 화면·Excel 표시 |
| --- | --- |
| `STUDENT` | 학생 |
| `TEACHER` | 담당교사 |
| `M1` / `M2` / `M3` | 중1 / 중2 / 중3 |
| `H1` / `H2` / `H3` | 고1 / 고2 / 고3 |
| 기존 `NULL` | 미지정 |

유효한 조합은 세 가지뿐이다.

1. 학생과 중1~고3 중 하나의 학년
2. 담당교사와 학년 없음
3. migration 이전 명단을 위한 구분·학년 모두 없음

새 등록과 Excel 가져오기는 1번 또는 2번만 허용한다. 3번은 기존 데이터를
읽고 나중에 수정할 수 있게 하기 위한 호환 상태이며 새로 만들 수 없다.

기존 `source` 값은 학생/담당교사와 혼동되지 않도록 화면과 Excel에서
`구분`이 아니라 `등록 시점`으로 표시한다. 값의 의미와 저장 값
`PRE_REGISTRATION`, `IN_PROGRESS`는 바꾸지 않는다.

## 3. 새 참가자 일괄 추가

### 3.1 화면 구조

`참가자 추가` 대화상자의 `새 참가자` 모드는 하나의 동적 입력 목록을
사용한다.

```text
소속 조직

[+ 참가자 추가]

이름 | 참가자 구분 | 학년 | 삭제
...

[닫기] [N명 명단에 추가]
```

- 대화상자를 처음 열면 참가자 행은 0개다.
- `+ 참가자 추가`를 누를 때마다 한 행을 추가한다.
- 새 행의 참가자 구분 기본값은 `학생`, 학년은 미선택이다.
- 참가자 구분을 `담당교사`로 바꾸면 학년 값을 지우고 학년 컨트롤을
  비활성화한다.
- 참가자 구분을 다시 `학생`으로 바꾸면 학년을 새로 선택해야 한다.
- 행마다 삭제 버튼을 제공한다.
- 최대 30행까지 허용하며 한도에 도달하면 추가 버튼을 비활성화하고 한도
  안내를 표시한다.
- 행이 없거나 유효하지 않은 행이 있으면 제출 버튼을 비활성화한다.
- 제출 버튼은 `N명 명단에 추가`로 현재 유효 입력 수를 보여준다.

넓은 화면에서는 이름, 구분, 학년, 삭제를 한 행으로 보여준다. 좁은 화면에서는
각 참가자 행을 구분되는 카드 또는 묶음으로 쌓아 다른 사람의 필드와 혼동되지
않게 한다. 입력 행 목록은 대화상자 안에서 스크롤하되 제목, 조직 선택,
하단 작업 버튼의 구분감은 유지한다.

### 3.2 검증과 중복 확인

- 이름은 기존 정규화 규칙을 적용하고 1~100자로 제한한다.
- 학생은 중1~고3 중 정확한 한 학년을 반드시 선택한다.
- 담당교사는 학년을 전송하지 않는다.
- 빈 이름, 학생 학년 미선택, 30명 초과는 클라이언트와 서버에서 모두
  거부한다.
- 같은 요청 안의 중복 이름과 같은 조직의 기존 참가자 이름 중복은 기존
  중복 확인 절차를 유지한다.
- 중복 확인 대화상자를 거쳐 재제출해도 각 행의 참가자 구분과 학년을
  그대로 보존한다.
- 서버 검증, 중복 확인, revision 충돌 또는 네트워크 오류가 발생하면 모든
  입력 행을 유지한다.
- 일괄 생성은 전체 성공 또는 전체 실패다. 일부 참가자만 생성하지 않는다.

30명은 API 요청 하나의 상한이다. 실제 운영상 학생 수가 약 20명인 것은 화면
구성 기준일 뿐 별도의 20명 제한으로 사용하지 않는다.

## 4. 기존 참가자 추가와 명단 수정

기존 참가자를 프로젝트에 추가할 때도 이번 프로젝트의 참가자 구분과 학년을
확인한다.

- 이전 프로젝트 이력이 있으면 가장 최근 명단 스냅샷의 구분과 학년을 추천
  기본값으로 보여줄 수 있다.
- 추천은 자동 확정이 아니다. 사용자는 새 프로젝트 등록 전에 값을 확인한다.
- 이전 이력이 없거나 이전 값이 `미지정`이면 학생 기본값과 학년 미선택으로
  시작한다.
- 담당교사 선택 시 학년 없음 규칙은 새 참가자와 동일하다.

현재 프로젝트의 기존 명단 행은 이름·소속을 수정하는 기존 흐름에서 참가자
구분과 학년도 함께 수정할 수 있다. 기존 `미지정` 행을 처음 저장할 때는 새
등록과 같은 유효성 규칙을 적용한다. 현재 프로젝트의 스냅샷만 바꾸며 다른
프로젝트의 과거 명단은 수정하지 않는다.

권한과 프로젝트 상태 제한은 기존 규칙을 유지한다. 조직 담당자는 자신에게
허용된 프로젝트·조직 범위에서만 수정할 수 있고, 진행 중 또는 종료 상태의
변경 권한도 기존 정책을 따른다.

## 5. 명단 조회, 필터 및 요약

참가 명단 표의 주요 열은 다음과 같다.

```text
고유 ID | 이름 | 조직 | 참가자 구분 | 학년 | 등록 시점 | 상태 | 작업
```

- 기존 구분·학년 없는 행은 두 열 모두 `미지정`으로 표시한다.
- 담당교사의 학년은 `-`로 표시한다.
- 참가자 구분 필터는 `전체`, `학생`, `담당교사`, `미지정`을 제공한다.
- 학년 필터는 `전체`, `중1`~`고3`, `미지정`을 제공한다.
- 기존 이름 검색, 조직 필터, 상태 필터와 함께 적용한다.
- 필터는 화면 표시만 바꾸며 Excel 내보내기 범위에는 영향을 주지 않는다.

프로젝트 개요에는 기존 예상·실제·증감과 별도로 현재 조회 권한 범위의
학생 수와 담당교사 수를 표시한다. `미지정`은 어느 쪽에도 추정하여 넣지
않으며 전체 명단 수에는 포함한다. 조직별 요약과 Excel 요약 시트에도 학생과
담당교사 열을 추가하되 같은 계산 규칙을 사용한다.

학생/담당교사 수는 명단 상태와 혼동하지 않게 활성 명단 기준으로 계산한다.
취소 명단은 전체 내보내기에는 포함되지만 현재 참가 인원 유형 집계에는
포함하지 않는다.

## 6. Excel 내보내기 확인

`엑셀 내보내기`를 누르면 바로 다운로드하지 않고 확인 대화상자를 연다.
대화상자는 다음 정보를 표시한다.

- 프로젝트 이름
- 전체 명단 수
- 활성 명단 수
- 취소 명단 수
- 활성 학생 수
- 활성 담당교사 수
- 현재 화면의 검색·조직·상태·구분·학년 필터와 관계없이 전체 명단을
  내보낸다는 안내
- 취소 명단도 상태 열과 함께 포함된다는 안내

버튼은 `취소`, `엑셀 내보내기`로 구성한다. 사용자가 확정해야 기존 workbook
생성 및 다운로드를 시작한다. 생성 중에는 중복 클릭과 대화상자 닫기를 막고
진행 상태를 보여준다. 실패하면 대화상자와 사용 맥락을 유지하고 재시도 가능한
오류를 표시한다.

명단 시트는 다음 열을 포함한다.

```text
고유 ID | 이름 | 조직 | 참가자 구분 | 학년 | 등록 시점 | 상태 | 최종 수정
```

기존 데이터의 구분과 학년은 `미지정`, 담당교사의 학년은 빈 값으로
내보낸다. 요약 시트에는 전체·조직별 학생 수와 담당교사 수를 추가한다.
원본 Excel 파일을 서버에 보관하지 않는 현재 정책은 유지한다.

## 7. Excel 가져오기

가져오기 템플릿과 열 매핑에 다음 필드를 추가한다.

- 참가자 구분
- 학년

새로 가져오는 모든 행은 참가자 구분이 필수다. 허용 표시값은 `학생`,
`담당교사`이며 학생은 `중1`, `중2`, `중3`, `고1`, `고2`, `고3` 중 하나를
반드시 가져야 한다. 담당교사의 학년 셀은 비어 있어야 하며 값이 있으면
검증 오류로 안내한다.

이 두 열이 없는 기존 형식 파일은 값을 추정해 가져오지 않는다. 미리보기
단계에서 누락된 필수 열과 올바른 입력 예시를 명확하게 안내하고 실제 저장을
차단한다. 유효하지 않은 행은 행 번호, 이름, 오류 필드를 보여준다.

가져오기 중 기존 참가자와 매칭해도 프로젝트 명단 스냅샷에는 파일에서 확인한
구분과 학년을 저장한다. 가져오기는 기존처럼 원자적으로 처리하고, 오류가
있으면 일부 행만 저장하지 않는다.

## 8. API 계약

공용 계약 패키지에 다음 enum을 추가한다.

```ts
ParticipantRole = "STUDENT" | "TEACHER"
StudentGrade = "M1" | "M2" | "M3" | "H1" | "H2" | "H3"
```

일괄 등록 요청은 `names` 배열 대신 구조화된 행을 받는다.

```ts
{
  organizationId: string;
  participants: Array<{
    name: string;
    role: ParticipantRole;
    grade: StudentGrade | null;
  }>;
  confirmDuplicateNames: boolean;
  expectedRevision: number;
}
```

단건 등록의 `confirmedParticipant`와 `newParticipant`에도 `role`, `grade`를
추가한다. 명단 수정 요청은 이름·조직 외에 `role`, `grade`를 선택적으로
받되 두 스냅샷 필드는 한 쌍으로 검증한다.

명단 응답은 기존 데이터 호환을 위해 다음을 nullable로 제공한다.

```ts
role: ParticipantRole | null;
grade: StudentGrade | null;
```

새 등록 요청에서 빠진 구분, 학생의 빠진 학년, 담당교사의 학년 값은
`422 VALIDATION_FAILED`로 거부한다. 중복 확인과 stale revision 오류 계약은
기존 상태 코드를 유지한다.

가장 최근 역할·학년 추천은 참가자 마스터에 복사하지 않는다. 기존 참가자
후보 응답에 최근 유효 스냅샷을 선택적으로 포함하거나, 이미 조회한 명단
이력에서 프론트엔드가 계산한다. 구현 시 권한 범위를 넘어선 프로젝트 이력을
노출하지 않는 쪽을 선택하며, 서버가 추천값을 계산하는 경우 현재 사용자가
열람 가능한 이력만 사용한다.

## 9. D1 migration과 무결성

새 append-only migration은 `project_roster_entries`에 nullable 스냅샷 열
두 개를 추가한다. 기존 행은 명시적인 `NULL` 상태로 남기며 역할이나 학년을
이름 또는 프로젝트 시점으로 추정하지 않는다.

DB와 서비스는 다음 조합만 허용한다.

```text
NULL / NULL                    기존 호환 행
STUDENT / M1..H3               학생
TEACHER / NULL                 담당교사
```

SQLite에서 기존 테이블 재생성이 과도하다면 유효 조합을 강제하는 INSERT 및
UPDATE trigger를 추가한다. 서비스 검증만으로 끝내지 않고 직접 SQL 또는 이후
코드 실수로 잘못된 조합이 들어오는 것도 차단한다. trigger는 migration으로
존재하던 `NULL / NULL`과 이를 올바른 값으로 보정하는 수정은 허용한다.

원격 적용 전에는 기존 운영 runbook대로 D1 export와 checksum을 만든다.
이번 migration 번호를 배포 전 pending migration 허용 목록에 명시적으로
추가하고, 적용 뒤 다음을 검증한다.

- 새 열이 존재하고 기존 명단 행 수가 변하지 않음
- 기존 행의 스냅샷이 `NULL / NULL`임
- 잘못된 역할·학년 조합이 없음
- `PRAGMA foreign_key_check` 결과가 비어 있음
- 프로젝트·명단·감사 행 수와 주요 합계가 적용 전과 일치함

배포·복구 문서에는 이번 migration의 적용 순서, 검증 SQL, 복구 절차를 함께
추가한다.

## 10. 원자성, 감사 및 오류 처리

- 최대 30명의 일괄 생성은 기존 D1 guarded batch를 사용한다.
- 참가자 마스터, 명단 스냅샷, 감사 이벤트가 모두 성공해야 commit한다.
- 프로젝트 revision은 일괄 요청 한 번에 한 번만 증가한다.
- 감사 이벤트에는 batch ID와 각 참가자의 이름, 역할, 학년을 남겨 변경 이유를
  추적할 수 있게 한다.
- 명단 스냅샷 수정도 변경 전·후 역할과 학년을 기존 감사 이력에 포함한다.
- 중복 확인 재시도 전에 project revision이 바뀌면 전체 요청을 거부한다.
- Excel 가져오기 역시 잘못된 한 행 때문에 일부만 저장하지 않는다.
- Excel 내보내기는 읽기 동작이므로 서버 상태를 바꾸지 않는다.

## 11. 테스트 전략

테스트는 실패하는 테스트를 먼저 작성한 뒤 최소 구현으로 통과시키는 순서를
따른다.

### 계약과 migration

- enum과 학생/담당교사 역할·학년 조합
- 새 일괄 요청의 1~30행 제한과 이름 정규화
- 단건 추가·수정 요청의 역할·학년 교차 검증
- 응답의 nullable legacy 값
- migration 전 기존 DB fixture가 데이터 손실 없이 올라가는지
- trigger가 세 가지 유효 조합만 허용하는지

### Worker 서비스

- 학생과 담당교사를 섞은 일괄 생성 성공
- 학생 학년 누락, 담당교사 학년 포함, 30명 초과 전체 실패
- 중복 확인 전후 역할·학년 보존
- batch 전체 원자성, project revision 1회 증가, 감사 내용
- 기존 참가자 최근 스냅샷 추천과 새 프로젝트 확인
- 현재 명단 스냅샷 수정 및 과거 프로젝트 불변
- 기존 `NULL / NULL` 명단 조회와 올바른 값으로 보정
- 구분·학년 필터 및 권한 범위
- 활성 학생·담당교사 요약과 미지정·취소 제외
- Excel 가져오기 필수 열·값 검증과 전체 원자성

### Web

- 0행 초기 상태, 행 추가·삭제, 최대 30행
- 학생 기본값, 학년 필수, 담당교사 전환 시 학년 초기화
- 모바일과 데스크톱에서 참가자 행 구분
- 실패·중복 확인·stale revision 뒤 입력 보존
- 기존 참가자 추천값 표시와 재확인
- `미지정`, 담당교사 학년 `-`, 등록 시점 열 이름
- 구분·학년 필터와 기존 필터 조합
- Excel 내보내기 확인 대화상자의 수치와 범위 안내
- 확인 전 다운로드 없음, 확인 후 1회 다운로드, 실패 후 재시도
- workbook 열 이름·표시값·요약 수치
- 가져오기 누락 열과 행별 오류 안내

### 전체 검증

- 포맷 검사와 전체 TypeScript 검사
- 전체 단위·Worker 통합 테스트
- Web production build
- Chromium E2E
- Worker deploy dry-run
- 로컬 D1 신규 설치와 기존 fixture migration
- 운영 배포 전 D1 backup 및 배포 후 health·schema·집계 smoke check

## 12. 완료 기준

- 운영자는 한 대화상자에서 최대 30명의 이름, 학생/담당교사, 정확한 학년을
  구분해 등록할 수 있다.
- 학생은 중1~고3 학년 없이는 새로 등록되지 않고 담당교사는 학년을 갖지
  않는다.
- 역할과 학년은 프로젝트별 스냅샷이며 과거 프로젝트가 이후 참가로 바뀌지
  않는다.
- 기존 명단은 추정 없이 `미지정`으로 유지되고 운영자가 올바르게 보정할 수
  있다.
- 명단 표와 Excel은 `참가자 구분`과 `등록 시점`을 혼동하지 않는다.
- 프로젝트 개요와 Excel 요약에서 활성 학생 수와 담당교사 수를 확인할 수
  있다.
- Excel 내보내기 전 전체·활성·취소 범위와 필터 무시 정책을 확인한다.
- 이전 형식 Excel은 누락된 필수 열 안내와 함께 안전하게 거부된다.
- 기존 권한, 프로젝트 상태, 예상/실제 집계, 감사, revision과 원자성 규칙의
  회귀가 없다.

## 13. 범위 밖

- 참가자 마스터에 현재 학년 또는 영구 역할 저장
- 학년 자동 승급
- 과거 프로젝트 명단 일괄 보정
- 학생/담당교사 외 참가자 구분
- 반, 학교급 범위, 출생연도 등 추가 학생 정보
- 한 요청 30명을 넘는 대용량 UI
- 화면 필터 결과만 Excel로 내보내기
- 취소 명단을 내보내기에서 제외하는 옵션
