# CI E2E 신뢰성 복구 설계

## 목표

현재 사용자 인터페이스와 E2E 시나리오를 다시 일치시키고, 참가자 추가 대화상자의 실제 클릭 방해 문제와 CI 로컬 서버의 TLS 잡음을 제거해 `main` CI 전체를 통과시킨다.

## 원인

- 조직 일괄 추가 UI가 페이지 내 체크박스에서 `조직 선택 추가` 대화상자로 변경됐지만 E2E는 이전 DOM을 계속 찾는다.
- 참가 명단 필터가 상단 셀렉트에서 표 헤더 팝오버로 변경됐지만 E2E는 이전 셀렉트를 직접 찾는다.
- 새 참가자 대화상자는 하나의 비스크롤 폼 안에 참가자 행과 하단 액션을 함께 배치해, 내부 행 추가 버튼이 하단 액션 영역 아래로 들어가 클릭을 가로막는다.
- Playwright는 자체 서명 HTTPS를 무시하지만 `workerd`는 CI에서 반복되는 TLS 경고를 출력해 실패 분석을 방해한다.

## 설계

### 조직 선택

공통 E2E 도우미가 `조직 선택 추가` 버튼을 누르고, 열린 대화상자 안에서 조직 체크박스를 선택한 뒤 `선택한 N개 조직 추가`를 누른다. 조직 연결을 수행하는 모든 시나리오는 이 실제 사용자 흐름을 사용한다.

### 명단 필터

E2E는 표 헤더의 필터 아이콘 버튼을 먼저 누른 다음 포털로 열린 필터 메뉴 안의 셀렉트를 조작한다. 필터를 바꿀 때마다 같은 헤더 버튼으로 메뉴를 다시 열어 현재 상호작용 계약을 검증한다.

### 참가자 추가 대화상자

새 참가자 모드의 폼을 `조직 선택`, `스크롤 가능한 참가자 편집 영역`, `고정 하단 최종 액션`으로 분리한다. 참가자 행을 추가하는 버튼은 스크롤 영역의 마지막 요소로 유지하고 최종 제출/닫기 액션과 겹치지 않게 한다. 작은 화면에서도 동일한 구조를 유지한다.

### 로컬 E2E 서버

외부 통신이 없는 격리 E2E이므로 로컬 서버와 Playwright base URL을 HTTP로 통일한다. 운영 HTTPS 설정에는 영향을 주지 않는다.

## 검증

- 대화상자 구조와 스크롤 영역을 검증하는 컴포넌트 회귀 테스트
- 갱신한 개별 Playwright 시나리오의 실패 후 성공 확인
- 전체 단위 테스트, 정적 검사, 포맷 검사, 웹 빌드, Worker dry-run, 전체 E2E 실행
- `main` 푸시 후 GitHub Actions 완료 상태 확인

## 범위 제외

- 현재 조직 선택 모달이나 표 헤더 필터 UX의 재설계
- 운영 배포 방식 변경
- 실패와 무관한 화면 리팩터링
